# Сравнение VPG01_nomem и VPG01_mem

Две версии бота на базе VPf09 для учебного задания: одна **без памяти**, вторая с **SQLite + ChromaDB**.

## Кратко

| Критерий | VPG01_nomem | VPG01_mem |
|----------|-------------|-----------|
| История диалога | Нет | Все реплики в SQLite |
| Перезапуск процесса | Контекст теряется | Контекст из SQLite в system prompt |
| Документы PDF/DOCX/TXT | One-shot разбор | Индексация в Chroma, RAG |
| `/clear` | Нет | Сброс SQLite |
| `/forget` | Нет | Сброс Chroma |
| Зависимости | Без chromadb | chromadb + SQLite (stdlib) |

## Сценарии проверки

### 1. Имя и город

1. Сообщение: «Меня зовут Аня, я из Казани.»
2. Сообщение: «Как меня зовут и откуда я?»

**Ожидание**

- **nomem:** модель не знает имени (или отвечает, что не помнит прошлых сообщений).
- **mem:** ответ с «Аня» и «Казань», опираясь на блок контекста из SQLite.

### 2. Длинная переписка (12+ реплик)

**Ожидание**

- **nomem:** каждый ответ изолирован, ранние факты из серии не учитываются.
- **mem:** в базе копятся все реплики; в промпт уходит полная история (или её хвост, если сработал лимит символов API).

### 3. Документ `data/sample_knowledge.txt`

1. Загрузить файл.
2. **nomem:** «Разобрать файл» → один ответ с фактами; второй вопрос по файлу без повторной загрузки — бот не может.
3. **mem:** сохранить в Chroma → вопрос «Какой адрес офиса КотоКорп?» → ответ по RAG.

### 4. Рестарт бота

После сценария 1 остановить и снова запустить `python bot.py`.

- **nomem:** имя не восстанавливается.
- **mem:** при старте в логе `SQLite контекст готов`; имя по-прежнему доступно.

### 5. Очистка контекста

На **mem** после запоминания имени выполнить `/clear` → подтвердить.

- Диалог в SQLite пуст; имя не используется.
- Документы в Chroma остаются до `/forget`.

## Как память меняет поведение

**Без памяти (nomem)**

- Предсказуемо: нет «залипания» на старых ошибках модели.
- Неудобно для диалога: пользователь должен повторять факты в каждом сообщении.
- Документы только как разовый разбор — подходит для быстрого summary, не для Q&A по файлу.

**С памятью (mem)**

- Естественный чат: имя, предпочтения, уточнения работают в рамках окна и после рестарта.
- Нужно следить за накоплением: устаревший контекст в SQLite может влиять на ответы до `/clear`.
- RAG по документам даёт ответы другими формулировками, не только дословным цитированием последней реплики.

## Удобство разработки

- **nomem** проще отлаживать: один запрос — один промпт, меньше moving parts.
- **mem** ближе к продуктовому боту: отдельно тестировать SQLite (юнит-тесты), Chroma (интеграция), команды `/clear` и `/forget`.

## Рекомендации

- FAQ, справка, разовые вопросы → **nomem** или mem с частым `/clear`.
- Персональный ассистент, обучение по документам, длинные сессии → **mem**.
